## Result and ownership

The replay CLI consumes one data-only file, enforces an 8 MiB UTF-8 input limit, prints command/event counts and final phase, and exits 1 with the first divergence index/kind or a specific validation/rejection reason. It bounds actual bytes read, closes the file, and never treats record text as code or paths. The existing Q01 launcher supplies caller-relative resolution, read-only input mounting and `--network none`, unchanged.

Record parsing now validates closed command IDs, numeric portions of instance/intent IDs, fight and full gauntlet descriptors, encounter/part definitions, intent definitions and references, statuses and Wards, ledger references, carried pools, phases and victory resets. Full initial snapshots remain simulation input; neither factory defaults nor expected events/final state feed replay. Whole gauntlets include recorded `continue` commands and run-wide revisions. Unfinished player and between-fights exports remain accepted (brief §12 amendment).

The corpus has **24 parity records** (22 new plus the two unchanged Q02 seeds): seven complete encounter wins, six form witnesses, a complete trio gauntlet win, a gauntlet defeat, five named edge witnesses, and two unfinished exports. Some edge names share a trace that witnesses several requirements. Every positive record was generated by the real public API, with embedded v1 content, and replayed before writing. The 13 hostile records are explicitly separate negative mutations. Oversized and malformed inputs are generated under `/tmp` during tests.

```markdown
## Records and replay (Q03)

Exported records embed their content, complete initial state, accepted commands
with ordered events/revisions, and expected final state. Fight and whole-gauntlet
records replay through the same rules API, including `continue` commands and
run-wide revisions. Unfinished attempts in `player` or `between-fights` also export
and replay; their outcome is the final phase.

From the repository root:

    ./poc-002-component-combat/bin/run replay poc-002-component-combat/fixtures/parity/gauntlet-win-trio-v1.json

Input paths are relative to the caller's directory. Docker mounts the named input
read-only and disables networking. Replay reads no files named by record content
and executes no record text. The input cap is **8,388,608 UTF-8 bytes (8 MiB)**,
including whitespace. Oversized inputs, unknown fields/versions/kinds/IDs, invalid
integers, impossible states and rejected commands fail with a specific reason and
exit 1. Success exits 0 and prints `commands`, `events` and `outcome`. Divergence
identifies the first zero-based `commandIndex` and `events`, `revision` or
`final-state`; a final-state mismatch uses the command count.

The 24-record corpus in `fixtures/parity/` is the future C# parity gate: the two
brief seeds, every encounter, every form, gauntlet win/defeat, five edge witnesses,
and unfinished exports. Every record embeds frozen v1 content. Read
`fixtures/parity/README.md` before intentionally authoring a new version; never
edit parity JSON by hand. Negative fixtures live separately in `fixtures/hostile/`.
Run `./poc-002-component-combat/bin/run test` for all contract/parity/hostile checks.
```
