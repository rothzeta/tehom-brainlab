## Concrete findings

1. **Lifecycle classification is unreliable for these OMP sessions.** Herdr repeatedly reported `idle` while the title spinner and worker output showed active work. `agent prompt ... --wait` returned `agent_prompt_stalled` despite successful delivery, and standalone waits immediately returned idle. The Coordinator correctly inspected before retrying and did not submit duplicate tasks. It resorted to title-spinner polling and 400/500-line terminal reads. This does not establish that a five-second startup window alone is the cause: the lifecycle state stayed idle throughout active turns.
2. **Agy's permission dialog was also misclassified.** Herdr reported `done` while the visible terminal was requesting approval. The observer used the actual UI to identify it and asked the user. The user first approved the launcher help command once, then gave standing authorization to answer command dialogs only within this Agy experiment across its Coordinator and workers. The observer inspected each command before approving it. No global permission setting was changed.
3. **OMP violated Coordinator boundaries.** It read `justfile`, `scripts/doctor.sh`, and `bin/doctor`, then checked Git status/history/branches. After worker delivery it executed `git rev-parse experiment/orch2-omp-delivery`, Git log/status, and branch inspection itself. It also specified internal path-resolution and duplicated argument-validation choices in the worker assignment. Successful delivery does not erase these role findings. An attempted native `hub` message failed with an unknown-agent result; actual workers and task delivery used Herdr.
4. **Claude repeated a smaller metadata violation.** Its initial shell command included `git rev-parse HEAD`; a post-implementation read included `git branch --show-current`. It did not directly inspect production content, run acceptance tests, review diffs, or merge. Terminal convenience diffs displayed during worker activity are not counted as Coordinator model reads; recorded tool inputs substantiate the findings here.
5. **Durable reports improved persistence, but did not eliminate terminal reconstruction.** Claude now committed the merge handoff, correcting the previous trial's terminal-only outcome. Its report fields nevertheless describe an evidence-only successor and say the exact SHA is in the terminal, so the Coordinator read terminal blocks to recover it. OMP had exact checked revisions in reports but still consumed extensive terminal history rather than bounded report blocks. The brief explicitly permitted a checked predecessor in durable evidence and a final evidence-commit SHA in the terminal; descriptive revision fields are avoidable.
6. **Agy required permission administration.** Its Coordinator asked for a worker command approval that the observer had just handled. The observer used the question's write-in response to relay the user's standing authorization, identify the already-resumed worker, and prevent duplicate keys. That assistance changed permission administration, not the feature specification or canonical role/workflow. Subsequent dialogs are inspected and approved only within this experiment. The Coordinator also ran initial `git status` and `git log -1 --oneline`, violating its technical-metadata boundary. It repeatedly used 30-line terminal progress reads through native 20/30-second Schedule callbacks rather than lifecycle status plus only the final report block. Native scheduling here is waiting within the same session, not an alternate worker-launch route.
7. **Agy prefilled a successful review outcome.** Its review assignment requested independent checks but supplied a handoff example with `verification: passed`, `review: no-blockers`, and `blockers: null` rather than placeholders. This is an avoidable bias in the assignment; the Reviewer must determine those fields from evidence. The observer did not alter the assignment during the experiment.
8. **Agy integration expanded its context beyond its own task.** While resolving delivery-report revision fields, the worker read the old `/tmp/check-brainlab-orchestrator-scope.py`, inspected older Claude/Codex trial histories, read an older Codex Implementer report and Claude terminal evidence, and searched prior snapshots for `tested_revision`. The new worktrees prevented write collisions, but did not enforce read isolation from earlier evidence. This weakens any claim that Agy delivery was independent of prior trial examples. The worker then requested non-workspace access to the main checkout's old acceptance report; the observer denied that access because it was outside the bounded trial approval. After observing the interruption, the Coordinator sent its own corrective Herdr prompt restricting the worker to its assigned worktree and reiterating evidence completion. The worker subsequently searched the older snapshot directory again despite that restriction. No observer feature implementation advice was supplied.
9. **Agy returned complete with uncommitted final evidence.** Initial delivery `6a1b2b113ba4646ee38cdb36adff8c8c1381b679` contained the merge report body, but the final structured top block was added afterward and left uncommitted. The [initial observer scope check](agy-initial-scope-failure.json) failed with a dirty Implementer report; the Coordinator had nevertheless claimed no deviations and strict adherence. The observer returned this concrete failure to the Coordinator for worker-owned correction, without changing source or performing the repair. The Coordinator's first correction required a report to contain the SHA of its own future commit, reproducing the circular requirement. The observer then explicitly clarified the original permitted distinction between a tested predecessor in the durable report and the evidence-only successor SHA in the terminal. The next committed correction then contained `f935ad1615a1a129d332906b3a0e4450ae728e83`, a nonexistent commit, instead of actual predecessor `f935ad1eb4498e6bd64fb1449aa44a6eb336634c`. The observer verified the mismatch with `git cat-file -t` and returned a final bounded report-only finding. The final report-only correction committed a valid predecessor block and returned actual successor `1c4d43937d0ff28162b4acd26c504fa6679c2a45`, with clean state and unchanged technical content. These corrections include protocol assistance, so Agy's result is not an unassisted handoff success. Its report body still attributes the invalid SHA to amend regeneration and overstates subsequent read isolation; the observer's concrete history above supersedes those claims.
10. **Codex enforced the handoff contract.** After its first worker completion, it read the report header and requested the missing top structured block and exact candidate reference before independent review. It delegated that correction instead of checking Git itself. It still made 13 terminal-read calls (15–25-line progress reads and a 23-line final handoff read) after timed waits and loaded broad role/workflow/Herdr/schema context upfront. No numeric context budget was assigned.

## Interpretation and next experiment

This measures one simple, fully specified task per harness in this cohort. It supports portable workflow selection and external worker delegation, with observed differences in role adherence. It does not establish conflict handling, blocking-review repair, destination movement, long-running reliability, or numeric context savings. Skill metadata visibility and workflow-body loading are separate observations; native invocation of both technical skills was not a requirement and is not claimed for every worker.

Keep the canonical definitions stable for now. The next useful change is a concrete lifecycle/handoff interface: trustworthy worker state, a bounded structured report block, and exact reviewed/tested/delivered references that survive terminal loss. Fixing that interface should be tested before adding permanent orchestration machinery.
