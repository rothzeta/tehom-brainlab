# Review workflow

1. Identify the exact change or revision being reviewed.
2. Give the Reviewer the task scope and relevant acceptance conditions.
3. Ensure the Reviewer receives sufficient project context but not the Implementer's reasoning transcript unless needed.
4. Collect concrete findings.
5. Return blocking findings to the responsible Implementer.
6. Re-review materially changed work when necessary.
7. Do not treat the absence of comments as proof that verification passed.
